# TeleDav 前端重设计规格

## 1. 概述

本规格定义 TeleDav 网盘 Web 控制台前端的全面重设计。目标是替换当前基于 Flutter Material 默认样式的界面，打造一个以网页端为先、具备网盘控制台气质、引导式且自有视觉语言的新前端。

### 1.1 背景

当前前端（`web/lib/`）使用 Flutter Material 3 默认 `AppBar + TabBar` 结构，存在以下问题：

- 视觉上太"原生 Flutter"，缺乏网盘产品的识别度
- 顶部 Tab 切换文件/设置/Jobs，不符合主流网盘的侧栏导航习惯
- WebDAV 功能被埋在设置里，不够突出
- 缺少首次使用引导，新用户面对空界面无从下手
- 大量圆角元素，视觉偏柔，缺乏控制台的"硬朗"感

### 1.2 设计目标

- **网盘控制台形态**：左侧常驻导航 + 主内容区，类似 Google Drive / 坚果云
- **网页端优先**：针对桌面浏览器优化，键鼠交互流畅
- **自有视觉语言**：莫兰迪鼠尾草绿 + 米灰背景 + 直角硬朗风，区别于默认 Flutter
- **WebDAV 突出**：独立一级菜单 + 文件页横幅（可关闭）
- **引导式**：首次向导 + 空状态内联兜底，降低上手门槛
- **简单易用**：每个界面职责单一，操作路径清晰

### 1.3 技术约束

- 维持现有 Flutter Web 技术栈（不切换框架），重设计通过自定义 `ThemeData`、布局组件和自绘元素实现，避免引入重度依赖
- 复用现有 `ApiClient` 和 `models.dart`，不改动后端 API 契约
- 保持 Go 后端 `internal/api`、`internal/webdav` 不变

## 2. 范围

### 在范围内

- 全部现有界面的重设计：登录、文件浏览、传输队列、Telegram 连接、WebDAV 接入、设置
- 新增首次设置向导流程
- 新增 WebDAV 独立接入页
- 自有设计系统的定义（配色、排版、组件规范）
- 侧栏导航 + 面包屑 + 空状态引导等导航与引导机制
- WebDAV 横幅的可配置开关（前端本地存储偏好）

### 不在范围内

- 后端 API 的新增或改动（除非前端重设计显式需要新的配置项，需另行评估）
- 移动端 App 或原生客户端
- 用户账号体系（仍为单用户密码登录）
- 国际化 i18n（界面文案中文优先，结构上预留但不实现多语言）
- 文件预览、缩略图、全文搜索等新功能（仅重设计现有功能的表现层）

## 3. 设计系统

### 3.1 配色

采用莫兰迪低饱和暖灰色系，主色为鼠尾草绿。所有颜色不带圆角暗示，纯平面色块。

| 角色 | 色值 | 用途 |
|---|---|---|
| 主色 Primary | `#7FA88C` 鼠尾草绿 | 导航选中项、主按钮、进度条、Logo 底色、强调链接 |
| 主色深 Primary Dark | `#4E7A66` | 主色文字态、链接文字、图标强调 |
| 画布 Canvas | `#EFEBE4` 米灰 | 应用整体背景 |
| 侧栏 Sidebar | `#E7E2D9` 暖灰 | 左侧导航栏背景 |
| 卡片 Card | `#F7F4EE` 浅米 | 内容卡片、表格、模态背景 |
| 卡片边框 Border | `#DCD6CC` | 所有分隔线、卡片描边 |
| 分隔线 Divider | `#E8E2D9` | 表格行分隔、次要分隔 |
| 正文 Text | `#3D3935` 深褐灰 | 主要文字 |
| 次要文字 Text Muted | `#7C746A` | 辅助说明、面包屑非当前段 |
| 弱化文字 Text Faint | `#9C9389` | 占位符、表头、禁用态 |
| 成功 Success | `#DAE6DF` 底 / `#4E7A66` 字 | "就绪"状态标签 |
| 警告 Warning | `#F5E8D9` 底 / `#A87A3E` 字 | "上传中"、"待办"步骤标签 |
| 错误 Error | `#F0D9D9` 底 / `#A15B5B` 字 | "失败"状态标签 |
| 点缀 Accent | `#A87A3E` 暖橙 | 仅用于非主色的强调点缀（如警告），不作为主色 |

所有组件采用 **全直角**（border-radius: 0）。进度条、状态标签、按钮、卡片、输入框均无圆角。

### 3.2 排版

- 字体栈：`'Google Sans', 'Segoe UI', system-ui, -apple-system, sans-serif`；代码/地址用 `ui-monospace, 'SF Mono', Menlo, monospace`
- 基础字号：正文 13px，辅助 11px，表头/标签 10px 大写带 letter-spacing
- 字重：常规 400，强调 500，标题 600，Logo 700
- 行高：正文 1.5，紧凑列表 1.3

### 3.3 间距与栅格

- 基础间距单位 4px，常用 8/12/16/24
- 侧栏宽度 208px（桌面），移动端折叠为图标条 56px
- 内容区最大宽度不设硬上限，内边距 18px
- 卡片内边距 14-16px

### 3.4 组件规范

**按钮**
- 主按钮：主色实底 `#7FA88C` + 白字，直角，padding 6px 12px
- 次按钮：卡片底 `#F7F4EE` + 边框 `#C9BFB2` + 深字，直角
- 文字按钮：仅主色深文字 + 下划线（如"复制"、"显示"）
- 危险按钮：错误色底 `#F0D9D9` + `#A15B5B` 字（如"断开"）

**输入框**
- 卡片底 + 边框 `#C9BFB2`，聚焦时边框转主色 `#7FA88C`
- 无圆角，高度适配 13px 字号

**状态标签**
- 小尺寸（10px），低饱和底色 + 同色系深字，直角，padding 1px 6px
- 三态：就绪（绿）、进行中（橙）、失败（红）

**表格**
- 直角，行高 36px，行分隔 `#E8E2D9`
- 表头：10px 大写、letter-spacing、弱化文字色
- 列：名称（弹性）/ 大小（固定 70-90px）/ 状态（固定）/ 操作（固定）

**提示条 Callout**
- 左边框 3px 主色 + 浅主色底 `#E2EDE6`，用于 WebDAV 横幅、引导提示
- 图标 + 文字 + 操作链接 三段式

## 4. 信息架构与导航

### 4.1 应用骨架

```
登录页
  └ 登录成功
      ├ 首次进入（无 Telegram 连接且无已完成向导标记）→ 设置向导（3步）→ 控制台
      └ 非首次 → 控制台（默认文件页）

控制台（左侧导航 + 主内容区）
  ├ ▸ 文件（默认首页）
  ├ ⇅ 传输队列
  ├ ✈ Telegram
  ├ ▣ WebDAV
  └ ⚙ 设置
```

### 4.2 左侧导航栏

固定在左侧，208px 宽，包含：

- **Logo 区**：绿色方块 Logo + "TeleDav" + 副标题"网盘控制台"
- **存储用量卡片**：显示已用/总量 + 进度条（数据来自现有 `StorageConfig`，若后端暂无用量字段则显示固定占位并标注待后端支持）
- **导航项**：5 个一级入口，每项含图标 + 文字；选中项主色实底直角块；传输项带未读计数徽标；Telegram 项带连接状态圆点
- **底部状态栏**：当前 Telegram 连接状态 + 用户标识

移动端（< 768px）侧栏折叠为 56px 图标条，文字隐藏，点击图标切换。

### 4.3 面包屑

文件页顶部显示当前路径面包屑（如 `/ 文档 / 工作`），非当前段用次要文字色，分隔符 `/` 用更弱色。点击任意段可跳转该目录。

## 5. 界面规格

### 5.1 登录页

- 全屏画布背景，居中卡片（宽 280px）
- 顶部：绿色 Logo 方块（48px）+ "TeleDav" + "基于 Telegram 的私有网盘"
- 卡片内：密码输入框（占位"应用访问密码"）+ 全宽主色登录按钮
- 卡片下方辅助文字："首次使用？登录后会有引导。"
- 错误信息显示在按钮上方，错误色

### 5.2 首次设置向导

**触发条件**：登录后检测 `TelegramAuthStatus.connected == false` 且本地无已完成向导标记（localStorage `teledav.wizard.completed`）。满足则进入向导，否则直接进控制台。

**布局**：左侧步骤导航（160px）+ 右侧当前步骤内容卡片。

**步骤导航**：
- 标题"初始设置"
- 3 个步骤项，每项含编号圆方块（选中态主色实底、未完成灰色）+ 步骤名
- 当前步骤主色深字 + 加粗，其余弱化色
- 底部"跳过，稍后设置"链接（次要色，下划线）

**步骤 1 — 连接 Telegram**：
- 说明文字解释文件将存入 Telegram 频道
- 手机号输入框（占位 +86 格式）
- "发送验证码 →"主按钮
- 进入 `needsCode` 态后同屏切换为验证码输入 + "验证"
- 进入 `needsPassword` 态后同屏切换为两步验证密码输入 + "验证"
- 底部 callout 提示："验证码会发送到你手机的 Telegram 客户端（不是短信）"

**步骤 2 — 选择存储频道**：
- 说明文字解释频道是文件实际存放处
- 频道列表（单选），来自 `fetchTelegramChannels`
- 每项：频道名 + 频道 ID，选中态主色；"使用"按钮
- "新建专用频道"输入框 + 创建按钮（对应 `createTelegramChannel`）
- 完成后调用 `selectTelegramChannel`

**步骤 3 — 挂载 WebDAV**：
- 显示 WebDAV 服务器地址（复制按钮）
- 显示账号密码（密码默认掩码，"显示"切换）
- 各平台挂载教程入口（Windows / macOS / Linux，展开式）
- "完成"主按钮 → 写入 `teledav.wizard.completed = true` → 进入控制台文件页

向导在每步完成后自动前进；任意步失败显示错误色提示，不阻断已完成的步骤。

### 5.3 文件页（默认首页）

**布局**：主内容区顶部工具栏 + WebDAV 横幅（可选）+ 文件列表。

**工具栏**：
- 左：当前路径面包屑
- 右：上传、新建文件夹、刷新（次按钮）

**WebDAV 横幅**（受设置开关控制，默认开）：
- 主色左边框 callout，显示当前目录的 WebDAV 完整地址（如 `http://localhost:8080/webdav/文档/工作`，由 `window.location.origin + '/webdav/' + 当前目录相对路径` 拼接）+ "复制"链接
- 复制按钮将完整地址写入剪贴板
- 帮助文案："本目录 WebDAV："前缀
- 路径计算：当前目录相对路径来自 `TreeResponse.directory.path`（去掉前导 `/`）；根目录时地址为 `origin + '/webdav/'`

**文件列表**：
- 直角表格，表头：名称 / 大小 / 状态 / 操作
- 文件夹行：绿色文件夹图标 + 名称（主色深），大小显示"—"，点击进入
- 文件行：文件类型图标 + 名称 + 大小（人类可读，KB/MB/GB）+ 状态标签
- 操作列：文件夹显示 `›` 进入；文件显示 `›` 详情
- 空状态：见 5.8

**上传交互**：点击"上传"触发文件选择器（复用 `file_picker`），选择后立即调用 `uploadBytes` 并刷新列表与传输队列。

### 5.4 传输队列

**布局**：顶部标题栏 + 任务表格。

**标题栏**：
- "传输队列" + 状态摘要（如"3 个进行中 · 1 个失败"）
- 右侧"刷新"次按钮

**任务表格**（列：文件 / 阶段 / 进度 / 操作）：
- 文件列：图标 + 文件名 + 目标路径
- 阶段列：阶段文字（如"分块上传"、"下载"），用对应语义色
- 进度列：进度条（主色填充灰底）+ 百分比文字；失败任务显示错误摘要（如"网络超时 @chunk 7"，错误色）
- 操作列：进行中显示"—"；失败显示"重试"主按钮（对应 `retryJob`）
- 数据来自 `fetchJobs`，`stage == 'failed'` 的任务 `retryable` 为 true

**轮询**：进入页面时拉取一次；建议每 5 秒轮询刷新（轻量，仅 `/api/jobs`）。

### 5.5 Telegram 连接页

**已连接态**：
- 顶部卡片：连接状态（绿色圆点 + "已连接"）+ 用户标识 + 手机号（掩码）+ "断开"危险按钮
- 存储频道区：标题"存储频道" + 频道列表
  - 每项：选中态主色圆点 / 未选灰色圆点 + 频道名 + 频道 ID；使用中项标"使用中"绿色小标；其他项"切换"主按钮
- 底部：新建频道输入框 + "创建"按钮

**未连接态**（作为兜底，向导跳过后的入口）：
- 与向导步骤 1 相同的手机号 → 验证码 → 密码流程，单卡片居中布局
- 顶部步骤指示条（复用 5.8 的步骤条组件）

### 5.6 WebDAV 接入页（独立一级菜单）

**布局**：标题 + 双栏内容。

**标题**："▣ WebDAV 接入" + 副标题"把网盘挂载到电脑，像本地磁盘一样访问"

**左栏 — 接入信息卡片**：
- 服务器地址：monospace 显示完整 URL（如 `http://localhost:8080/webdav/`）+ "复制"链接
- 账号：用户名（来自会话/配置）+ 密码（默认掩码，"显示"切换明文）
- 状态：服务运行指示（绿色圆点 + "服务运行中"）

**右栏 — 挂载教程卡片**：
- 标题"挂载教程"
- 3 个平台条目（展开式）：Windows（映射网络驱动器）/ macOS（Finder 连接服务器）/ Linux（rclone / davfs）
- 每条点击展开显示分步操作（纯静态文案，前端硬编码）

**地址来源**：WebDAV 根地址基于当前页面 `window.location.origin + '/webdav/'`，无需后端额外接口。账号用户名为固定 `admin`（单用户），密码为应用登录密码（提示用户使用登录密码）。

### 5.7 设置页

**分组卡片式布局**，每组含标题 + 配置项。

**存储组**：
- 默认分块大小（输入框，单位标注 MB，对应 `default_chunk_size`）
- 暂存上限（输入框，单位 GB，对应 `max_staging_bytes`）
- 下载缓存 TTL（输入框，单位秒，对应 `download_cache_ttl_seconds`）

**外观组**：
- "文件页显示 WebDAV 横幅"开关（默认开），状态存 localStorage `teledav.prefs.webdavBanner`
- 预留主题切换结构（本期不实现深色模式）

**关于组**：
- 应用版本、Telegram 会话状态、应用密码是否已配置（只读展示，来自 `StorageConfig`）

**保存**：底部"保存设置"主按钮，调用 `updateStorageConfig`；保存成功显示成功 toast。

### 5.8 空状态与内联引导

**设置进度步骤条**（当向导未完成时在文件页顶部显示）：
- 三段标签：① 连 TG / ② 选频道 / ③ 挂 WebDAV
- 已完成段：成功色底 `#DAE6DF` + 绿字 + ✓
- 当前待办段：警告色底 `#F5E8D9` + 橙字 + 编号
- 未开始段：中性灰底 + 弱字
- 点击任意未完成段跳转对应设置入口

**空文件夹状态**：
- 居中大图标（📁）+ "这里还是空的" + 引导文案（根据设置进度动态：未连 TG → "先连好 Telegram，就能上传文件了"；未选频道 → "先选好存储频道，文件才有地方放"）
- 主按钮跳转下一步设置入口
- 可选：次要链接"了解 TeleDav 工作原理"

**空传输队列**：图标 + "暂无传输任务"，无引导按钮。

## 6. 用户偏好与本地存储

前端使用 localStorage 存储非敏感偏好（键名统一前缀 `teledav.`）：

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `teledav.wizard.completed` | boolean | `false` | 是否已完成首次向导（用户主动完成或跳过均置 true） |
| `teledav.prefs.webdavBanner` | boolean | `true` | 文件页是否显示 WebDAV 横幅 |

不存储任何密码、会话或 Telegram 凭据到前端。

## 7. 数据与 API 对接

全部复用现有 `ApiClient`，无新增后端接口。映射关系：

- 登录：`login(password)`
- 文件树：`fetchDirectory(parentId)`、`createDirectory`、`uploadBytes`
- 传输：`fetchJobs`、`retryJob`
- Telegram：`fetchTelegramAuthStatus`、`startTelegramAuth`、`verifyTelegramCode`、`verifyTelegramPassword`、`disconnectTelegram`、`fetchTelegramChannels`、`selectTelegramChannel`、`createTelegramChannel`
- 配置：`fetchStorageConfig`、`updateStorageConfig`

**存储用量展示**：现有 `StorageConfig` 无用量字段。本期文件页侧栏用量卡片显示固定占位（如"用量统计待后端支持"），不臆造数据。如后续后端增加用量接口，再接入。

## 11. 待确认 / 风险

- **存储用量数据源**：现有后端无用量统计接口，侧栏用量卡片本期为占位。是否需要后端新增接口由用户后续决定，不在本规格强制范围。

- **移动端适配**：侧栏折叠为本期目标，但主验证以桌面浏览器为准；移动端视为尽力而为。
- **挂载教程文案**：三平台教程为前端硬编码静态文案，需实施时核对各平台当前 WebDAV 挂载步骤的准确性。
